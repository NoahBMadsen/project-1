What I Learned
Reflections from a 2-week engineering shadow
1
"Asking for help is engineering, not weakness."
The 20-minute rule: try seriously for 20 minutes, then escalate. Going dark when stuck doesn't make the problem go away - it makes it compound while everyone assumes work is happening.
2
"AI proposes, human curates."
AI-assisted coding is a multiplier on what you already understand, not a substitute for understanding. The human judgment layer is where engineers earn their keep.
3
"Infrastructure is invisible to users."
Building the foundation feels productive because it's tangible. But real engineering is shipping a slice end-to-end. Deciding what to cut matters as much as deciding what to build.
4
"Show me where in MY code this is referenced."
When an AI asks for something you don't recognize, don't frantically provide it or dismiss it. Ask the AI to prove the requirement by reading the actual code.
5
"Match your tools to the shape of the work."
Cycles are for ongoing teams. Milestones are for projects with an end date. Default settings aren't always correct for your situation.
6
"The next engineer should be able to run it without asking you a single question."
If a machine-specific thing is required to run your project, that requirement needs to be documented. That's the difference between code and a product.
The Biggest Takeaway
"Senior engineers don't ship perfect code. They ship code, then iterate. The skill I needed most wasn't coding - it was saying 'I'm stuck, here's what I tried, can you help?'"
