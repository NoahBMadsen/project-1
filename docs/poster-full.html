What I Did
2-Week Software Engineering Shadow Program
Shadowed a senior software engineer for two weeks in a hybrid format - in-person office days and remote distributed team simulation via Slack and Zoom. Learned the full software development lifecycle from ideation to deployment.
The Timeline
Day 1 - Hello World
Set up development environment. Created first GitHub repository. Built and deployed a website to GitHub Pages.
Day 2 - Real Engineering
Observed daily standup and sprint planning meetings. Whiteboarded web architecture and database fundamentals.
Day 3 - Project Ideation
Brainstormed app ideas using AI. Evaluated 3 finalist concepts. Selected Bramble as the capstone project.
Weekend - Learning JavaScript
Completed freeCodeCamp JavaScript projects. Learned variables, loops, conditionals, and functions.
Remote Day - Distributed Work
Full remote simulation. Standups on Zoom. Slack threading etiquette. End-of-day written reports.
Architecture Day
Created wireframes in Excalidraw. Made tech stack decisions. Designed database schema with 5 tables.
Build Days
Set up Linear for project management. Built authentication, database, and deployed to Vercel. Merged 5 pull requests.
Final Sprint
Integrated AI plant ID, community map, journal, and invasive species detection. Shipped to bramblemap.com.

Features
AI Plant Identification
Snap a photo and Bramble uses the Pl@ntNet API to identify the species with confidence scoring.
Safety Information
Every plant shows edible, medicinal, toxic, and invasive status. Unverified plants display a clear safety warning.
Invasive Species Detection
Cross-references 1,500+ species from the USGS national invasive species registry.
Community Map
Interactive map shows plant discoveries from all users within 25 miles using PostGIS spatial queries.
 
Foraging Journal
Every scan auto-creates an entry with species name, GPS coordinates, date, and confidence score.
Plant Database
Search 34,000+ plant species from the USDA database. Filter by edible, medicinal, toxic, or invasive.
Secure Authentication
One-click Google sign-in via Supabase. No passwords to remember.
3 Authoritative Data Sources
Pl@ntNet API for real-time ID, USDA PLANTS for taxonomy, USGS US-RIIS for invasive species.

What I Learned
Reflections from a 2-week engineering shadow
1
"Asking for help is engineering, not weakness."
The 20-minute rule: try seriously for 20 minutes, then escalate. Going dark when stuck doesn't make the problem go away - it makes it compound.
2
"AI proposes, human curates."
AI-assisted coding is a multiplier on what you already understand, not a substitute for understanding. The human judgment layer is where engineers earn their keep.
3
"Infrastructure is invisible to users."
Building the foundation feels productive. But real engineering is shipping end-to-end. Deciding what to cut matters as much as deciding what to build.
4
"Show me where in MY code this is referenced."
When an AI asks for something you don't recognize, ask it to prove the requirement by reading the actual code.
5
"Match your tools to the shape of the work."
Cycles for ongoing teams. Milestones for projects with an end date. Default settings aren't always correct.
6
"The next engineer should run it without asking a single question."
If a machine-specific requirement exists, document it. That's the difference between code and a product.
The Biggest Takeaway
"Senior engineers don't ship perfect code. They ship code, then iterate. The skill I needed most wasn't coding - it was saying 'I'm stuck, here's what I tried, can you help?'"
